# System contract graph

## Core message

Represent accepted system behavior, topology, interfaces, state, operations, policy,
and verification as linked Markdown contracts reconciled after proven change.

## Value

Gives agents explicit traversal paths across end-to-end outcomes and implementation boundaries.

## Assumptions

- Maintained relationships improve decisions more than they cost to keep fresh.
- Markdown links can express the required graph without a graph database.

## Evidence and collisions

The attachments support a system map and rich context, not a typed graph. Existing
docs cover fragments, and no thin-slice retrieval result yet shows the graph's gain.

## Trade-offs and recommendation

Precise context and impact analysis versus staleness and modeling overhead. Prototype
the smallest edge set and call it accepted contract state, not runtime truth.
