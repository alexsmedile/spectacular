# Orient

Read the Project Anchor, named direction sources, and the selected `MISSION.md`. Lead with plain
project direction, current Mission outcome, owner, Contract/Git baseline, validation mode, current
Objective/Run, blocking Gaps or stops, and one continuation or owner gate. Do not preload history,
every record, or generated catalogs.

Use supported typed `show` and `check` commands when they understand the Mission schema. Under
`manual-bootstrap`, inspect canonical Markdown and exact referenced files directly; an incompatible
CLI refusal is a tooling Gap, not evidence that the Mission is invalid.

If several active Missions exist, state which one the session will operate and why. Do not silently
combine their authority, criteria, scope, or mutable state.
