# Governance choice and cadence

Ordinary work is the default. The owner explicitly chooses a Mission when frozen
scope and formal proof help; risk alone does not activate one.

| Choice | Useful artifact | Execution boundary |
|---|---|---|
| Direct work | Relevant context; no new file required | Existing task authorization |
| Plan first | One durable plan in plans/ | Native host planning controls |
| Coordinate several slices | Short linking plan or campaign | Existing task and integration boundaries |
| Delegate a bounded task | Appropriate context and return receipt | Explicit delegation authority and isolated writes |
| Govern a frozen slice | Contract and Mission with supporting proof | Supported governed commands and owner gates |

There is no required progression through these choices. The historical
[D30 ladder](../decisions/D30-gated-pipeline-work-boards-and-graduated-orchestration.md)
is an advanced coordination model, not a prerequisite for ordinary work.

## Cadence

Keep one coherent outcome active. Verify the real implementation at meaningful
boundaries and record useful results in its existing plan. Split domains, modules,
phases, or delivered tranches when they become independently useful.

A Mission retains its formal completion requirements. A Contract keeps mechanical
validation and its amendment/version rules regardless of the surrounding work.
Decision validation is recommended; a soft Decision does not require a Mission.
