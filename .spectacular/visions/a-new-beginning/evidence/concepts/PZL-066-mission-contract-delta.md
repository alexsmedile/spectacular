# Mission as approved contract delta

## Core message

Define a mission as a bounded desired change from current capability truth, with
non-goals, affected interfaces, risks, evidence, permissions, and stop conditions.

## Value

Makes execution accountable to an explicit behavioral delta rather than a task list.

## Assumptions

- Every consequential work unit can name an affected capability baseline.
- Contract-preserving work can express a zero-behavior delta clearly.

## Evidence and collisions

Approved specs plus PLAN/SPEC-DELTA already approximate this model. Mission could
unify them or erase distinct direction and execution approvals.
Source 007 makes the delta a transaction over a versioned system graph and separates
Mission intent from multiple run attempts.

## Trade-offs and recommendation

One coherent work contract versus overloaded mission documents. Compare field-level
authority with SPC, PLAN, and SPEC-DELTA before choosing consolidation.
