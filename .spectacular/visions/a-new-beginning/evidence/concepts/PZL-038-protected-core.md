# Define a protected core

## Core message

Name the smallest set of capabilities that embodies Spectacular's proven product
value before evaluating peripheral deletions.

## Value

Prevents reduction from erasing the directory-as-contract insight, cheap signal
layer, request continuity, decisions, or current-truth loop.

## Assumptions

- The core can be stated behaviorally rather than as a list of existing files.
- Protected does not mean exempt from simplification.

## Evidence and collisions

The source nominates convention, intent, PLAN/TASKS lifecycle, requests/archive,
decisions, and specs/spec-sync. Its table is truncated, and earlier sources debate
whether specs and anchors should be eager or earned.
Source 006 supplies a competing behavioral core: baseline → capability contract →
mission delta → bounded run → evidence → reconciliation → resume.

## Trade-offs and recommendation

Stable reduction boundary versus prematurely protecting current implementation
shape. Define core outcomes and invariants first, then allow internal replacement.
Strong direction.
