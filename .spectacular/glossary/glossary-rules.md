# Glossary rules

Add one glossary file only when Spectacular gives a word a precise meaning that
changes how work is routed, stored, approved, retrieved, or interpreted.

Do not add general industry primitives such as UUIDv7, YAML, Git, Markdown,
pull request, branch, or slug unless Spectacular assigns that word an uncommon
operational meaning.

Each term file contains one concise definition, its practical boundary, and a
short `## Related` list of `[[links]]`. The glossary index is navigation only;
it does not duplicate definitions.
