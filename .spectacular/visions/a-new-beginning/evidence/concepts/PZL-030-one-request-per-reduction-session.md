# One request per reduction session

## Core message

Represent every reduction session as its own durable Spectacular request so each
cut has a plan, verification, and archived rationale.

## Value

Produces reviewable histories and makes future reintroduction decisions evidence-backed.

## Assumptions

- Every session has an accepted execution outcome before work starts.
- Nine request bundles add less cost than the history they preserve.

## Evidence and collisions

Current consequential requests normally derive from approved specs; exploratory
decisions belong in this Vision first. Creating nine requests while evaluating
whether Spectacular over-scaffolds work is self-contradictory.

## Trade-offs and recommendation

Durable rationale versus ceremony and duplicated planning. Use requests only for
approved implementation boundaries; keep investigation and decisions in the
Vision/concept workflow. Mixed.
