# Optional debt-prioritization pack

## Core message

If repeated user demand appears, a pack may supply a debt inventory and prioritization rubric; it
should not become a core collection or universal score.

## Value

Could help teams compare remediation work consistently when debt is an active operating concern.

## Assumptions

Users have recurring debt records and can provide evidence for scoring inputs.

## Evidence and collisions

Issue #41 records that core inclusion was already rejected and provides no usage evidence. It
conflicts with the reduction goal and protected-core threshold.

## Trade-offs and recommendation

Park the proposal. Reopen only after external demand or repeated local records justify a pack;
prefer transparent factors over a magic composite score.
