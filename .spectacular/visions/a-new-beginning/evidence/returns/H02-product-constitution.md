## Identity, users, and job

Spectacular is an AI-native project control plane for substantial software
projects. It governs shared intent, contracts, accountable work, evidence,
reconciliation, collaboration, and continuity. Host runtimes execute
implementation attempts; native tools perform repository and provider operations.

Its primary beneficiaries are solo founders, technical founders, project owners,
solo developers managing substantial or multiple projects, and small AI-native
teams. Humans and agents may collaborate asynchronously, but the accountable
project owner remains the primary beneficiary.

> Help me turn evolving ideas into maintainable, high-quality software by ordering
> the thinking, preserving shared decisions, safely distributing work, proving
> results, and always showing what should happen next.

## Umbrella promise

> Spectacular turns evolving software intent into shared contracts and accountable
> Missions, coordinating humans and agents through evidence-backed delivery so
> project owners can delegate with confidence and always recover what matters next.

## Protected loop and gates

```text
understand
→ explore
→ accept Capability Contract
→ design solution
→ accept Solution Contract
→ plan accountable Missions
→ execute through bounded actors
→ prove promised behavior
→ reconcile shared truth
→ resume from durable state
```

1. **Capability Contract acceptance:** desired success, behavior, boundaries, and evidence expectations are sufficiently understood.
2. **Solution Contract acceptance:** realization, constraints, decisions, risks, and proof strategy are coherent enough to authorize implementation.

Ceremony may compress for small, clear, reversible work; the invariants remain.
Spectacular owns both gates. Specialist work may be delegated, but acceptance and
integration authority return to Spectacular and the authorized owner.

## Owned responsibilities

Spectacular owns project grounding and accepted authority; uncertainty routing and
exploration governance; Capability and Solution Contract formation and acceptance;
Mission formation, dependencies, permissions, stops, and proof obligations;
responsibility routing and collaboration contracts; lifecycle authority and status;
evidence and independent-review routing; reconciliation; continuity, wayfinding,
and the next safe action; and deterministic workspace integrity through its CLI.

Delegation does not remove Spectacular's accountability for the loop's integrity.

## Mandatory-tool boundary

- Skill Core owns guided judgment and orchestration and is required for the complete experience.
- CLI is an ongoing deterministic support tool, not a one-time bootstrap utility.
- Git is the baseline history, collaboration, isolation, and recovery substrate.
- Host runtime owns inspection, edits, tests, bounded attempts, and runtime delegation.
- Native tools/providers own branches, commits, worktrees, PRs, checks, merges, deployments, credentials, and permissions.
- Companion skills own complete optional specialist workflows.
- Canonical state remains inspectable, versionable, recoverable, and manually repairable; a text editor alone does not provide the complete experience.

Spectacular must remain independent of mandatory companions, proprietary services,
specific providers, and specific coding runtimes—not independent of its own Skill
Core and CLI.

## Explicit non-goals

Spectacular is not a model host or coding runtime; generic scheduler or worker
queue; organizational PM suite; Git client/host; CI/CD or deployment platform;
universal specialist-work suite; documentation wiki; substitute for code, tests,
or observed behavior; autonomous authority over consequential decisions; or a
guarantee of flawless code, delivery, or market success.

## Failure test

> If Spectacular cannot preserve accepted intent, bind the work, prove the result,
> reconcile truth, and enable safe continuation, it has ceased to be Spectacular.

Distributed work additionally requires controlled convergence through provenance,
authority, handoffs, and integration responsibility.

## Accepted trade-offs and reversal consequences

- Owner-centered/multi-actor collaboration is core; enterprise administration is not.
- Owning the complete control loop is larger than a specification workspace, but removing proof, reconciliation, or continuity collapses the identity.
- Exploration and Solution Design require strong delegation/return contracts because Spectacular cannot perform every specialist discipline exhaustively.
- Host-owned execution protects portability; becoming an executor later would impose very high architectural cost.
- Required Skill Core and CLI trade tool-free parity for deterministic guarantees while keeping canonical state inspectable.
- Git is the baseline, but provider independence is mandatory.
- Quality is governed through decisions and evidence, not guaranteed.
- Collaboration belongs in core only where it protects delivery coherence.

## Rejected and deferred worlds

Rejected: integrated Mission executor; contracts-only knowledge workspace;
tool-free behavioral equivalence; managed proprietary runtime; PM-suite expansion.

Deferred: exact placement of Specwright, Wayfinder, adversarial review, technical
architecture, and Git adapters; Pageworks and Bugworks are proposed optional
companions; UXperto is deferred beyond this Constitution. S07 owns final
responsibility placement.
