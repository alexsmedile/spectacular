# Stable typed system contracts

## Core message

Use Capability, Component, Interface, State, Operational, and Policy as stable
semantic contract types, while allowing small projects to embed them together.

## Value

Creates precise ownership for behavior, topology, communication, persistence,
operations, and cross-cutting constraints.

## Assumptions

- Six types cover recurring distinctions without premature taxonomy.
- Semantic type does not require one file or directory per instance.

## Evidence and collisions

Existing flat schemas, axes, specs, policy, and architecture prove some distinctions
matter. Source 006 explicitly defers separate registries and custom policy language.

## Trade-offs and recommendation

Precision versus schema and routing cost. Trial types as headings/frontmatter in one
slice; promote identity only when independent retrieval or lifecycle is proven.
