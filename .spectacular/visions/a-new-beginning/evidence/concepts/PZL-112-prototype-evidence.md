# Prototype as uncertainty evidence

## Core message

Use a disposable prototype when interaction, feasibility, or system behavior is cheaper to
learn from a working artifact than from more prose.

## Value

Converts uncertain assumptions into observable evidence before production commitment.

## Assumptions

- The prototype has an explicit question, timebox, disposal boundary, and promotion gate.
- Product contracts and production engineering remain separate decisions.

## Evidence and collisions

Source 008 correctly challenges exhaustive static specifications but overstates the
alternative. PZL-102 already proposes a disposable thin slice for graph questions.

## Trade-offs and recommendation

Prototypes accelerate learning but often become accidental production code. Admit them as
an evidence strategy selected by uncertainty, never as the default replacement for specs.
