# GH-011 — Progressive loading and token footprint

## Plain-language focus

Measure actual loaded context, then reduce always-loaded routing and repeated workflow prose.

## Problem and evidence

The issue records router/workflow duplication and baseline drift: manual line counts changed
between audits, proving that a repeatable benchmark—not a one-time count—is required.

## Proposed direction

Lean router, compiled state views, frequency-weighted runtime cards, lazy niche routes,
compact policy output, and proportional bug handling with safety non-regression fixtures.

## Relationships and collisions

downstream. Earlier #4 content should be absorbed rather than implemented independently.

## Actionability

context, round trips, completion quality, or a weighted score.
