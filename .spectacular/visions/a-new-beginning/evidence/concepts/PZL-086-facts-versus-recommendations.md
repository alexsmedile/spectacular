# Separate facts from recommendations

## Core message

Architecture synthesis must label repository discoveries, human requirements,
assumptions, and agent-invented recommendations as different authority classes.

## Value

Prevents plausible technical proposals from masquerading as current-system facts.

## Assumptions

- Provenance labels stay readable and are enforced during review.
- Repository evidence can be cited precisely enough to audit.

## Evidence and collisions

The present intake repeatedly found stale counts and inferred behavior in proposals,
demonstrating the need directly.

## Trade-offs and recommendation

More explicit reasoning versus authoring overhead. Strong canonical rule for design
artifacts and generated deltas.
