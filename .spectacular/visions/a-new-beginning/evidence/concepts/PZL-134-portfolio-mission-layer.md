# Portfolio Mission layer

## Core message

Introduce a durable goal above several requests when one approved outcome genuinely requires
multiple independently reviewable work units.

## Value

Could preserve cross-request intent, dependencies, and checkpoints without overloading one plan.

## Assumptions

There are real goals that cannot be represented as one Mission/request with objective phases.

## Evidence and collisions

Issue #20 conflicts directly with sources that rename the bounded request itself to Mission. Its
artifact identity and relationship to PLAN/TASKS remain undefined and depend on #31.

## Trade-offs and recommendation

A new layer adds hierarchy and lifecycle cost. Jointly grill #20/#31 using one historical program;
prefer a linked-goal projection unless it proves insufficient.
