# PLAN Review

Confirm the seven required sections are present and ordered; at least two ordered milestones;
TASKS exists; cross-request dependencies use `[[...]]`; every milestone has an authoritative
validation check; lifecycle status is `planned|active|review|verified`; deliverables are concrete;
and any Decisions entry names an alternative. Reject hardcoded release versions in request prose:
use request slugs or build IDs. Doctor remains the mechanical authority for active-request structure.
