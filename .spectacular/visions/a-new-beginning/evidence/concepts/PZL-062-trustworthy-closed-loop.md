# One trustworthy closed loop

## Core message

Prioritize only features that strengthen understanding, capability design, bounded
planning, execution, proof, truth reconciliation, and later resumption.

## Value

Supplies a behavioral protected core and a severe scope filter for the refactor.

## Assumptions

- One delivery loop represents Spectacular's primary user value.
- Other project-coherence outcomes can wait or fit inside it.

## Evidence and collisions

Current capabilities already implement fragments of the loop, but no single
real-project test proves the complete experience. The execution step conflicts
with the current PRD boundary if interpreted as product-owned orchestration.
Source 007 adds an architectural graph and independent gates to the same loop,
increasing precision and maintenance cost together.

## Trade-offs and recommendation

Coherence and focus versus excluding valuable non-delivery workflows. Adopt the
loop first as an evaluation model; decide execution authority separately.
