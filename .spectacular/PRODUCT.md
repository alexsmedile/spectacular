# Product

Spectacular keeps project context useful across chats, agents, and delivery phases.
Small linked Markdown objects retain needs, domain meanings, choices, and plans.
Ordinary work starts directly from that context. Explicitly selected Missions add
frozen scope and formal proof; Contracts keep mechanical agreement and versioning.

The [Ontology](ONTOLOGY.md) defines objects and relationships. Root docs/ explains
the shipped product; runtime instructions live in skills/. Neither copies work
plans or creates a second authority for internal requirements.
