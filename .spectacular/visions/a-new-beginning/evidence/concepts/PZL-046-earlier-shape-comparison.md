# Use the earlier simple shape as a comparison

## Core message

Compare the target refactor against Spectacular's much smaller v0.4-era shape to
recover the adoption advantages of a simpler product.

## Value

Provides a concrete historical baseline and reveals later surface that may have
grown faster than user value.

## Assumptions

- Earlier size was a cause of adoption rather than merely an earlier maturity stage.
- Later capabilities can be removed without losing the product's differentiator.

## Evidence and collisions

The source cites 28 references at v0.4 versus 77 now but provides no adoption or
task-success comparison. Git history preserves the shape, not proof of superiority.

## Trade-offs and recommendation

Useful simplicity benchmark versus nostalgia and feature amnesia. Compare user
journeys and capability outcomes, not file count alone. Mixed.
