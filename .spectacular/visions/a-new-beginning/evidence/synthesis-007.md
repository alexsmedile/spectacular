# Synthesis checkpoint 007

## What Source 011 adds

Source 011 converts the complete open GitHub backlog into a dated portfolio view. The issue bodies
and comments add direct owner evidence about product friction, but their open status does not make
them accepted requirements. Twenty-three issues reduce to 22 atomic concepts because #17/#32 share
one intent-propagation contract and #18/#24 share a renderer foundation while retaining distinct
live-state concerns.

## Actionability lanes

### Narrow product-contract decisions

- propagate a durable goal and generate a readable delivery lead (PZL-131, PZL-136);
- state one next action at a true terminal boundary (PZL-140);
- define settled-decision states and authorization attribution (PZL-145, PZL-146);
- keep generic capture local and proposal-only (PZL-149).

These do not require a graph platform, new scheduler, or expanded scaffold.

### Measurable prototypes

- benchmark frequency-weighted runtime cards with deterministic projections (PZL-128, PZL-129);
- render derived ASCII/Mermaid views without making them authoritative (PZL-132);
- continue the already-working concept-grouped portfolio review prototype (PZL-133, PZL-138);
- test a proportional one-file Vision entry before retiring or expanding Vision (PZL-148).

### Architecture-dependent proposals

Portfolio Missions, live graph supervision, and executable nodes form one decision cluster
(PZL-134, PZL-135, PZL-139). The cluster cannot be implemented coherently until Mission means one
thing, node claiming and reintegration are specified, and sequential execution has been shown
insufficient.

### Parked or optional surface

Semantic retrieval waits on measured deterministic retrieval (PZL-130). AFK commit implementation
waits on execution and Git ownership (PZL-137). Collaboration files and commitlint belong behind an
earned pack/opt-in boundary (PZL-141, PZL-142). Dublin Core needs a real adapter consumer
(PZL-144). Debt scoring has neither core approval nor usage demand (PZL-147).

## Strongest new evidence

The corpus makes three prior uncertainties more concrete:

1. Vision has usage friction, so zero/marginal record counts cannot establish deadness.
2. Human-facing delivery artifacts need a plain-language lead before framework metadata.
3. Terminal continuity is a user-visible contract, not merely an internal state-machine detail.

It also validates this refactor workflow as a prototype for #19 and #30: source-shaped issues can
be preserved while concept grouping, contradictions, and actionability become derived views.

## Recommended next decision order

1. Close the five narrow product-contract choices above.
2. Decide the optimization objective and benchmark for retrieval work.
3. Jointly grill the Mission identity and executable-node cluster.
4. Use those answers to place graph visualization, AFK, and companion-skill responsibilities.
5. Leave optional adapters, packs, and semantic retrieval outside the core until demand appears.
