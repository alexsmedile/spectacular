# Handoff and Autopilot

Autopilot is explicit and non-default. Bind it to the exact Mission activation fingerprint,
Objective/claim scope, Contract/Git baseline, allowed operator actions, owner-required effects,
budgets, checks, expiry, stops, recovery, and return destination. Disclose resource enforcement as
`hard | observed | unsupported`; `hard` requires independently verified measurement and cancellation.

Promote an inline Objective before independent delegation so its file can carry exact outcome,
claims, dependencies, inputs, semantic/mechanical scope, authority, stops, and return contract.
Mission accountability remains with the owner; a host task/thread is only a destination pointer.

Fan out only cohesive mid-to-long work with disjoint claim ownership. Avoid tiny sessions,
recursive critic loops, and repeated full reviews. Finish working code, run focused checks, and batch
compatible review at the Mission's frozen level.

The receiver returns status, actor, final baseline/result, changed files, checks, native-provider
receipts, Evidence, remaining Gaps, budget use, recovery point, and one next action or owner gate.
It never changes Mission criteria, declares Evidence sufficient, or gains provider permission.
