# Synthesis checkpoint 004

## What Source 008 changes

Source 008 does not establish a new product world. It supplies operating patterns for the
graph-oriented and autonomous worlds already exposed by Sources 006 and 007: dependency
graphs, clean worker contexts, verifier separation, deterministic gates, external state,
and prototype-driven learning.

Its value increases after removing its universal language. The coherent composition is:

> A DAG represents durable dependency and join structure. A bounded state machine records
> each attempt. Specialized workers receive compiled context. Deterministic checks and
> risk-triggered independent review produce evidence. Canonical external state permits resume.

That model is stronger than either “one agent loops until done” or “every job becomes a
parallel graph.” It also fits PZL-103 without yet authorizing a scheduler.

## Preserved rules

1. Use explicit dependencies when they change eligibility, ordering, or joins.
2. Split only separable work; keep integration responsibility visible.
3. Compile bounded contexts with a minimum shared safety and output contract.
4. Put deterministic checks around properties that are mechanically verifiable.
5. Treat prototypes as evidence for a named uncertainty with a disposal boundary.
6. Separate consequential creation from review, but trigger independence by risk.
7. Calibrate human gates to consequence, never merely to diff size.
8. Persist the minimum state needed to verify a baseline and resume safely.
9. Preserve raw evidence through pointers and storage policy rather than prompt repetition.
10. Apply ordinary modularity and maintainability standards to agent-generated work.

## Absolutes rejected or narrowed

| Source 008 wording | Durable interpretation |
|---|---|
| graph over loop | graph for dependencies; state machine and bounded loops for attempts |
| GraphRAG over vector RAG | evaluate graph traversal for structural/global questions; retain routing and other retrieval where better |
| infallible ontology | reviewable accepted semantic contract with provenance and freshness |
| never self-review | self-check plus risk-triggered independent evidence review; no agent confidence as proof |
| always parallel skeptic nodes | fan out only when independence, risk, and latency justify coordination cost |
| raw logs in Markdown | durable artifact pointers with redaction, retention, and local/committed classes |
| PostgreSQL universal substrate | stack-specific consolidation option outside the portable core unless a server need is proven |

## Effect on graph adoption levels

Source 008 strengthens Level 0 modeling rules and supplies experiment hypotheses for Level
1. It does not validate a first-class graph store, scheduler, multi-agent default, GraphRAG
pipeline, ontology service, or graph-oriented workspace. The gate from checkpoint 003
therefore remains: measure a small linked-contract projection before Levels 2 or 3.

## Execution architecture tension

The Diamond pattern and isolated verifier nodes conflict directly with Source 006's
single-agent MVP and deferral fence. This need not be resolved as an all-or-nothing fleet
choice. A coherent progression is possible but not yet accepted:

1. one executor with deterministic checks;
2. one independent review attempt for high-risk claims;
3. parallel workers only after task-separability and merge tests;
4. generalized scheduling only after repeated workflows justify it.

This progression is a candidate decision packet, not an implementation plan.

## Infrastructure conclusion

PostgreSQL does not belong in the protected Spectacular core on current evidence. Its JSONB
and transactional features are real; pgvector is an extension; queue-like `SKIP LOCKED`
has explicit consistency caveats; property-graph support is version-bound. A future server-
backed companion could evaluate PostgreSQL, but the refactor should not acquire an
infrastructure dependency merely because one database can host several workloads.

## Updated decision order

1. Keep the independent stabilization defects separate from architecture intake.
2. Decide Spectacular's execution authority and portable-core boundary.
3. Define contract, implementation, observed, and evidence authority.
4. Decide graph adoption Level 0 or a measured Level-1 experiment.
5. Decide the minimum canonical resume manifest and artifact retention classes.
6. Define when independent verification and worker fan-out are required, optional, or forbidden.
7. Only then decide agent fleet, companion-skill boundaries, storage adapters, and CLI surface.
